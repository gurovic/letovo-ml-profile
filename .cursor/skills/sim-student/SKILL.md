# Тестовый ученик (sim-student)

## Роль

Симулировать одного студента, проходящего программу 8 класса, и интерпретировать его результат.

Отличие от `test-teacher`: тестовый учитель проверяет ясность материалов для преподавателя.
Тестовый ученик — **вероятностная модель памяти**: какие темы студент освоил, отработал, закрепил или забыл.

## Модель памяти (spacing effect)

Каждая тема переходит между состояниями при каждой встрече:

| Состояние | Смысл |
|---|---|
| `unseen` | Тема не встречалась |
| `met` | 1-я встреча: познакомился |
| `practiced` | 2-я встреча в окне ≤8 пар: отработал |
| `mastered` | 3-я встреча в окне ≤12 пар: закрепил |
| `forgotten` | Не повторил вовремя — забыл |

`student_capacity` ~ Beta(8, 2) — сила студента, масштабирует все вероятности переходов.

## Workflow

```
1. Запустить симуляцию одного студента:
   python sim/run.py --students 1 --verbose --seed <N>

2. Прочитать вывод — итог по состояниям и топ пробелов.

3. Интерпретировать:
   - Какие темы mastered (хорошо освоены)?
   - Какие forgotten/unseen (не дошли)?
   - Как соотносится с портретом выпускника Foundation §3?

4. Если нужен конкретный «слабый» или «сильный» студент:
   подбирать seed до нужного capacity.
```

## Формат вывода

```markdown
## Результат экзамена — студент #1
Capacity: 0.823  |  Итоговый балл: 0.71  |  Портрет выпускника: ✓ сформирован

| Компетенция | Балл | Статус |
|---|---|---|
| Программирует как инженер | 0.74 | ✓ |
...

**Топ пробелов:**
- …
```

## Параметры

| Флаг | Описание |
|---|---|
| `--students 1` | один студент |
| `--verbose` | показать лог по каждой паре |
| `--seed N` | воспроизводимый запуск |

## Когда применять

- После изменения `competency_map.yaml`: проверить, что маппинг работает.
- При анализе конкретной траектории студента.
- Для ручной калибровки параметров модели памяти (`StudentConfig` в `sim/student.py`).

## Файлы

- `sim/student.py` — модель памяти
- `sim/examiner.py` — оценка по компетенциям
- `sim/run.py` — CLI
- `sim/competency_map.yaml` — маппинг тем
