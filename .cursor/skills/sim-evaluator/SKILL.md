# Оценщик программы (sim-evaluator)

## Роль

Провести массовую симуляцию (N ≥ 20, рекомендуется 100) и вынести
системные рекомендации по программе — не по одному студенту.

## Workflow

```
1. Запустить оценку:
   python sim/run.py --students 100 --seed 42

   Сохранить отчёт:
   python sim/run.py --students 100 --seed 42 --out sim/results/latest.md

2. Прочитать AggregateReport:
   - graduate_profile_rate — доля студентов с полным портретом выпускника
   - competency_pass_rates — % прошедших порог по каждой компетенции
   - weak_topics — темы с низким mastered rate (системные пробелы)
   - strong_topics — хорошо усвоенные темы
   - recommendations — автогенерированные рекомендации

3. Интерпретировать и сформулировать конкретные предложения по программе:
   - Какие темы встречаются слишком редко?
   - Где нарушено окно повторения (gap > threshold)?
   - Какие компетенции системно недобираются?

4. При необходимости — предложить правки в docs/ktp/08.md
   (добавить пары практики, сдвинуть тему, добавить ДЗ с повторением).
```

## Параметры

| Флаг | Описание |
|---|---|
| `--students N` | количество студентов (рекомендуется 100) |
| `--seed N` | воспроизводимый прогон (0 = случайный) |
| `--out path` | сохранить отчёт в файл |

## Интерпретация результатов

| graduate_profile_rate | Вывод |
|---|---|
| ≥ 80% | Программа хорошо формирует выпускника |
| 65–80% | Приемлемо, есть точки роста |
| 50–65% | Требуется усиление повторения ключевых тем |
| < 50% | Критично: структура программы не обеспечивает усвоение |

## Что делать с рекомендациями

1. Системные пробелы (weak_topics) → проверить в `docs/ktp/08.md`:
   - сколько раз тема встречается? (поиск по КТП)
   - достаточен ли интервал между встречами?
2. Низкий pass rate по компетенции → найти модули, отвечающие за неё,
   и проверить плотность практики.
3. После правки КТП — перезапустить симуляцию и сравнить отчёты.
