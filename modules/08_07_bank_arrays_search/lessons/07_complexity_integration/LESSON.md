# Lesson Design: интеграция сложности

## A. Сценарий пары

| Поле | Значение |
|---|---|
| Модуль | Массивы: поиск и сортировка (`08_07`) |
| Название урока | Сравнение O(n²) и O(n log n), интеграция блока |
| Пара КТП | **48** |
| Длительность | 2 академических часа (80 минут) |
| Роль | интеграция |
| Открыть | `lesson.ipynb`, `bank_transactions_unsorted.csv` |
| Минимум сдачи | Таблица бенчмарка, `acceptance`, `REPORT`, `READY=True` |
| Домашнее задание | `homework.ipynb` |
| Canvas | не опубликовано |

---

## B. Ход пары

| # | Этап | ~мин | Критерий закрытия |
|---|---|---|---|
| 1 | Проверка корректности функций сортировки | 15 | обе функции проходят тест |
| 2 | Бенчмарк на 4 размерах | 25 | собрана таблица времени и ratio |
| 3 | Acceptance checklist артефакта | 15 | все пункты чек-листа закрыты |
| 4 | Финальный REPORT | 20 | вывод связан с экспериментом |
| 5 | Рефлексия блока 42-48 | 5 | зафиксирована в ДЗ |

---

## C. Если сбились

| Симптом | Действие учителя |
|---|---|
| Бенчмарк без проверки корректности | Сначала assert на сортировку, затем измерения |
| REPORT без чисел | Требовать ссылки на таблицу `table`/`risk_table` |
| READY=True при незаполненном чек-листе | Вернуть к блоку acceptance |

---

## D. Проектирование

- Зачем урок: завершить алгоритмический блок и перевести его в проверяемый артефакт.
- Центральная идея: сложность алгоритма проявляется в эксперименте на росте данных.
- Материалы: урок + ДЗ + эталон в `solutions.ipynb`.
