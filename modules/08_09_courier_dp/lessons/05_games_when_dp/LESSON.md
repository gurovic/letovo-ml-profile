### A. Чего хотим от пары

Главное — перенести DP на булево состояние игры и вывести переход через существование хода в проигрышную позицию соперника. Ученик строит таблицу, возвращает выигрышный ход и проверяет стратегию симуляцией.

Вторая цель — завершить модуль инженерным выбором метода. Ученик применяет явный чек-лист состояния, повторяющихся подзадач, перехода и порядка вычисления, сравнивая DP с прямым и жадным решением без декларации «DP всегда лучше».

## C. Если сбились

### Типичные ошибки

| Симптом / мысль ученика | Что сказать или показать |
|---|---|
| `win[0]` отмечен как выигрыш | «Игрок должен сделать ход, но камней нет. Может ли он продолжить?» |
| Позиция считается выигрышной, только если все ходы ведут в проигрыш | На позиции 3 показать один выигрышный ход; достаточно существования |
| Проверяется `win[current + move]` | Нарисовать направление хода: число камней уменьшается |
| `winning_move` возвращает любой допустимый ход | После хода проверить состояние соперника через готовую таблицу |
| Симуляция пересчитывает таблицу для каждого хода и зависает | Построить таблицу один раз до стартового количества; отделить анализ от исполнения |
| Период на первых 40 позициях объявляется теоремой | Попросить сформулировать «наблюдаем на диапазоне» и назвать, чего не хватает для доказательства |
| В чек-листе причины состоят из «DP подходит» | Требовать назвать конкретный параметр состояния и конкретную зависимость |
| Для прямой суммы предлагается DP | Спросить, какие конкурирующие решения сравниваются; если их нет, таблица избыточна |

## D. Проектирование

### Зачем урок

Предыдущие пары использовали числовой оптимум. Игра показывает, что DP хранит любой достаточный ответ подзадачи, в том числе булево значение. Финальный чек-лист предотвращает механическое применение DP там, где прямой проход или доказанный жадный выбор проще.

### Центральная идея

| Поле | Значение |
|---|---|
| Центральная идея | В игре позиция выигрышна, если существует ход в проигрышную позицию; DP уместен только при компактном состоянии, повторных подзадачах, ясном переходе и вычислимом порядке |
| Что поддерживает, но не отвлекает | Симуляция стратегии и исследование периода проверяют таблицу, но не вводят теорию игр |
| Данные урока | Наборы ходов и сценарии inline; CSV модуля не используются |

### Результаты обучения

1. Разметить выигрышные и проигрышные позиции на малом примере.
2. Реализовать таблицу `win` для произвольного набора ходов.
3. Вернуть выигрышный ход и проверить его симуляцией.
4. Отличить вычислительную гипотезу о периоде от доказательства.
5. Обосновать выбор DP, жадного или прямого метода по конкретным признакам задачи.

### Профессиональный контекст

Булевое DP используется в дискретных сценариях доступности, достижимости и противодействия, где ответ состояния — возможность гарантировать результат. Инженерный чек-лист фиксирует стоимость сложности: DP не выбирают по названию задачи, если прямое решение уже даёт требуемый артефакт.

### Решения учащегося

| # | Какой выбор делает учащийся | На что влияет |
|---|---|---|
| 1 | Какое булево значение получает базовая позиция | Корректность всей таблицы игры |
| 2 | Какой из нескольких выигрышных ходов вернуть | Конкретная стратегия при одинаковой гарантии |
| 3 | Какой метод рекомендовать для каждого сценария | Сложность, проверяемость и риск неверного оптимума |
| 4 | Какие причины включить в итоговую ноту | Аудируемость инженерного решения |
