### A. Чего хотим от пары

Главное — научить видеть повторяющуюся подзадачу и до кода формулировать одномерное состояние, базовый случай и переход. Ученик сравнивает обычную рекурсию с мемоизацией, затем самостоятельно строит DP 1D для минимального размена и максимума без соседних точек.

Побочно фиксируем инженерное требование: оптимальное число должно подтверждаться контрактами на граничных и недостижимых случаях, а для практического решения иногда требуется восстановить сам набор действий.

## C. Если сбились

### Типичные ошибки

| Симптом / мысль ученика | Что сказать или показать |
|---|---|
| В `ways_plain` нет базового случая для отрицательного `n` | «Что означает маршрут, который перескочил ниже нуля? Сколько таких допустимых маршрутов?» |
| Кэш записывается, но перед рекурсией не проверяется | На `n=5` обвести два повторных вызова одного `n`; попросить указать место чтения |
| `dp[0]` остаётся недостижимым | «Сколько монет нужно, чтобы набрать сумму 0?» |
| Для недостижимой суммы возвращается большое служебное число | Попросить сформулировать внешний контракт функции отдельно от внутреннего значения |
| Цикл использует `dp[current - coin]` при отрицательном индексе | На сумме меньше номинала показать, что Python прочитает элемент с конца |
| В максимуме без соседей складываются соседние значения | Попросить выписать два варианта: пропустить текущую точку или взять её вместе с ответом до предыдущей соседней |
| Greedy объявляется корректным после одного примера | Запустить перебор сумм 1…12 для `[1, 3, 4]`; различать эксперимент и доказательство |

### Дифференциация (кратко)

| | |
|---|---|
| Слабее базы | Дать готовую трассу `ways_plain(4)`; в размене сначала заполнить `dp` вручную для суммы 6; обязательны §§1–7 и ДЗ A1–A2 |
| Сильнее базы | Не показывать структуру `coin_plan`; потребовать обосновать корректность обратного прохода; Challenge ДЗ сделать обязательным |

## D. Проектирование

### Зачем урок

Ученик уже умеет писать рекурсию, но без состояния и повторных подзадач не может определить, когда кэширование или таблица действительно сокращают работу. Урок вводит единый язык DP до практической серии следующей пары.

### Центральная идея

| Поле | Значение |
|---|---|
| Центральная идея | Если подзадача задаётся одним параметром и повторяется, её ответ можно вычислить один раз и использовать в переходах DP 1D |
| Что поддерживает, но не отвлекает | Восстановление решения и контрпример жадному; оценка асимптотики формально не вводится |
| Данные урока | `coin_change_cases.csv`; `route_cost_grid_4x5.csv` копируется рядом, но на этой паре не используется |

### Результаты обучения

1. Сравнить обычную рекурсию и мемоизацию по числу вызовов.
2. Назвать состояние, базовый случай и переход для размена.
3. Реализовать `min_coins` с контрактом для недостижимой суммы.
4. Реализовать переход «взять или пропустить» для несоседних значений.
5. Найти вычислительный контрпример жадному размену.

### Профессиональный контекст

Мемоизация используется, когда сервис многократно запрашивает один и тот же дискретный подрезультат. Табличный размен моделирует кассовое решение с произвольными номиналами; восстановление плана отделяет вычисление метрики от выдачи исполнимого решения.

### Решения учащегося

| # | Какой выбор делает учащийся | На что влияет |
|---|---|---|
| 1 | Как представить недостижимое внутреннее состояние | Корректность перехода и внешний ответ `-1` |
| 2 | В каком порядке заполнять суммы | Доступность всех зависимостей к моменту вычисления |
| 3 | Какие данные хранить для восстановления монет | Возможность вернуть план, а не только оптимальное число |
