### A. Чего хотим от пары

Главное — закрепить DP 2D серией задач с разными предметными смыслами двух индексов. Сначала ученик возвращает максимум, маршрут и количество оптимальных маршрутов по сетке, затем переносит схему на два префикса строк для общей подпоследовательности и расстояния редактирования.

Побочно сравниваем метрики строк и фиксируем ограничение: одинаковая форма таблицы не означает одинаковый переход. Каждый новый переход выводится из смысла состояния.

## C. Если сбились

### Типичные ошибки

| Симптом / мысль ученика | Что сказать или показать |
|---|---|
| Для максимума границы заполнены нулями при отрицательных значениях | Попросить проверить, создаёт ли ноль несуществующий вход в клетку; использовать недостижимое малое значение |
| Количество путей увеличивается и при худшем кандидате | Разделить таблицы `best` и `count`; сначала определить лучший предыдущий результат |
| LCS ищет только соседние символы | Показать, что подпоследовательность допускает пропуски, но сохраняет порядок |
| Используются `a[i]` и `b[j]` при таблице с нулевой рамкой | Сопоставить клетку `(1, 1)` символам с индексами 0 и 0 |
| При восстановлении LCS символ добавляется без диагонального шага | «Какие два префикса уменьшились после использования общего символа?» |
| Расстояние редактирования берёт максимум | Для одной замены `cat → cut` спросить, ищем худшее или минимальное число действий |
| Общая подстрока продолжает длину после несовпадения | Подчеркнуть требование «подряд» и обнулить текущую цепочку |

### Дифференциация (кратко)

| | |
|---|---|
| Слабее базы | Обязательны §§1, 2, 4, 5 и 7; для LCS дать пустую таблицу 4×4 и одну заполненную диагональ; в ДЗ A1–A2 |
| Сильнее базы | Самостоятельно считать число оптимальных маршрутов и восстанавливать LCS; выполнить общую подстроку и Challenge по числу LCS-путей |

## D. Проектирование

### Зачем урок

После одной сеточной задачи ученик может ошибочно принять DP 2D за «алгоритм маршрута». Практика показывает общий принцип пары параметров и требует каждый раз вывести новый переход: максимум на сетке, согласование префиксов и минимальное число правок.

### Центральная идея

| Поле | Значение |
|---|---|
| Центральная идея | Двумерная таблица переносится между задачами через смысл пары параметров, но переход всегда выводится из допустимых последних действий |
| Что поддерживает, но не отвлекает | Восстановление, количество оптимумов и сравнение двух строковых критериев |
| Данные урока | Сетки и строки inline; внешние CSV не требуются для обязательной серии |

### Результаты обучения

1. Реализовать максимум, восстановление и количество оптимальных маршрутов.
2. Сформулировать состояние LCS через два префикса.
3. Реализовать длину и восстановление общей подпоследовательности.
4. Вывести переход расстояния редактирования из трёх последних операций.
5. Объяснить различие LCS, расстояния редактирования и общей подстроки.

### Профессиональный контекст

Сравнение последовательностей используется для сопоставления кодов статусов, журналов событий и версий строковых идентификаторов. Восстановленный результат нужен для диагностики: длина LCS или расстояние сообщает величину, а последовательность или цепочка операций показывает причину.

### Решения учащегося

|---|---|---|

| 3 | Какую строковую меру выбрать | Интерпретация сходства и диагностический вывод |
