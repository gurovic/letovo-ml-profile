## B. Ход пары

| # | Этап | ~мин | Критерий закрытия |
|---|---|---|---|
| 1 | Разбор `train_cli.py` и аргументов | 15 | понятно, какие флаги управляют запуском |
| 2 | Запуск CLI из ноутбука через subprocess | 25 | получен JSON с метриками |
| 3 | Проверка acceptance (включая leakage guard) | 20 | `duration_in_features == False` |
| 4 | Сравнение двух порогов в CLI | 10 | выбрана лучшая конфигурация по F1 |
| 5 | Фиксация минимума + ДЗ | 10 | запуск воспроизводится без ручных шагов |

## C. Если сбились

| Симптом | Действие учителя |
|---|---|
| `FileNotFoundError` на CSV | Проверить путь `../../data/bank_marketing_slim.csv` |
| `returncode != 0` в subprocess | Прочитать `stderr`, проверить аргументы `--data`/`--threshold` |
| Не понимают смысл CLI | Сопоставить с реальным сценарием «коллега запускает по README» |

---

## D. Проектирование

- Центральная идея: воспроизводимость начинается с стабильного CLI-запуска, а не только с ноутбука.
- Data/ML-контекст: операционная команда должна получать одинаковые метрики при одинаковой команде.
- Материалы: `lesson.ipynb`, `homework.ipynb`, `solutions.ipynb`, `train_cli.py`.
- Домашнее задание: сравнить два порога через CLI и дать рекомендацию.
