### A. Чего хотим от пары

Главное — превратить единичный запуск модели в воспроизводимый интерфейс: команда задаётся списком аргументов, процесс возвращает код завершения, stdout имеет JSON-контракт, stderr объясняет сбой. Учащийся пишет runner, запускает серию порогов и проверяет результат программно.

Запрет `duration` выходит за пределы ноутбука: CLI обязан возвращать `duration_in_features=false`, а acceptance gate отклоняет любой иной результат.

## C. Если сбились

### Типичные ошибки

| Симптом / мысль ученика | Что сказать или показать |
|---|---|
| Передаёт всю команду одной строкой | `subprocess.run` получает список: один элемент — один аргумент, без зависимости от shell |
| Использует `python`, а не `sys.executable` | «Как гарантировать, что запускается тот же интерпретатор, где установлен sklearn?» |
| Сразу вызывает `json.loads` при ошибке | Сначала return code; при ненулевом коде читать stderr |
| Путь `../../data/...` не работает | На этой паре CSV скопирован рядом: используйте `Path("bank_marketing_slim.csv")` |
| Сравнивает JSON как текст | Разобрать в dict и проверять ключи, типы и диапазоны |
| Gate не проверяет `duration` | Это критическая проверка; без неё этап не закрыт |

### Дифференциация (кратко)

| | |
|---|---|
| Слабее базы | Один runner, три порога, готовый список acceptance-полей |
| Сильнее базы | Пять порогов; сетка 3×3 seed; универсальная функция acceptance и анализ разброса |

## D. Проектирование

### Зачем урок

Предыдущие пары дали корректную модель и критерии, но результат зависел от состояния ноутбука. Пара вводит минимальную инженерную границу: стабильный CLI-вход и машиночитаемый выход, которые можно проверить и затем описать в README.

### Центральная идея

| Поле | Значение |
|---|---|
| Центральная идея | Воспроизводимый эксперимент имеет явные входные аргументы, проверяемый JSON-выход и диагностируемый сбой |
| Что поддерживает, но не отвлекает | Серия порогов повторяет отработанный ML-критерий |
| Данные урока | `bank_marketing_slim.csv`; `train_cli.py` жёстко исключает `duration` |

### Результаты обучения

1. Собрать безопасную команду `subprocess`.
2. Проверить return code и JSON-контракт.
3. Реализовать runner для threshold и seed.
4. Спроектировать acceptance gate, включая запрет `duration`.
5. Диагностировать ожидаемый сбой по stderr.

### Профессиональный контекст

CLI — минимальный интерфейс эксперимента для коллеги, scheduler или теста. JSON позволяет следующему шагу читать метрики без разбора человекочитаемого лога.

### Решения учащегося

| # | Какой выбор делает учащийся | На что влияет |
|---|---|---|
| 1 | Какие поля входят в JSON-контракт | Проверяемость результата |
| 2 | Какие условия составляют gate | Принятие или отклонение запуска |
| 3 | Какие threshold и seed сравнить | Устойчивость вывода |
