## 5. Результаты обучения

После модуля учащийся может:

1. **Различить** числовые и категориальные признаки и способ их кодирования.
2. **Применить** lambda и `.apply` для построчного преобразования.
3. **Вычислить** групповые агрегаты (`groupby`).
4. **Логировать** шаги preprocessing без декораторов.
5. **Валидировать** вход pipeline через `raise` при нарушении контракта.
6. **Собрать** признаки Recency, Frequency, Monetary из истории заказов (`groupby` по клиенту).
7. **Собрать** цепочку preprocessing, совместимую с моделью из модулей 2/4 (без обязательного `fit` модели в этом модуле).

## 18. Глоссарий модуля

| Термин | Определение в контексте модуля |
|---|---|
| Feature engineering | Создание и отбор признаков под задачу модели |
| Числовой признак | Столбец с упорядоченными числовыми значениями (дни, суммы); допускает арифметику |
| Категориальный признак | Столбец с конечным набором меток (тип оплаты, штат); арифметика без кодирования бессмысленна |
| Label encoding | Замена строковых меток числами 0, 1, … без учёта порядка; опасна для линейных моделей |
| lambda | Анонимная однострочная функция; в модуле — аргумент `.apply` для построчного transform |
| `.apply` | Построчное применение функции к DataFrame/Series; уступает по скорости векторной операции |
| `groupby` | Группировка строк по ключу с последующим агрегатом (sum, mean, nunique, max) |
| Recency (R) | Дни от последней покупки клиента до опорной даты; меньше — активнее |
| Frequency (F) | Число уникальных заказов клиента за весь период |
| Monetary (M) | Суммарная сумма оплат клиента за весь период |
| Опорная дата (ref_date) | Единая дата для всей таблицы, от которой отсчитывается Recency; нельзя брать отдельно для каждого клиента |
| Утечка времени (temporal leakage) | Использование признака, известного только после события прогноза; делает модель некорректной в продакшне |
| Контракт данных | Явно зафиксированные правила допустимых значений на входе pipeline; нарушение → raise |
| Лог шагов | Список успешно завершённых операций pipeline; записывается только после выполнения шага |
| Preprocessing pipeline | Упорядоченная воспроизводимая цепочка transform над таблицей; порядок шагов зафиксирован |

### 19.2. Gate итогового артефакта

| Критерий | Проверяемое свидетельство |
|---|---|
| Контракт входа | плохая схема/ключ/дата/оплата вызывает информативный `KeyError` или `ValueError` |
| Корректность RFM | 778 уникальных клиентов; сумма Frequency = 3500; сумма Monetary совпадает с payments |
| Производные признаки | `share_card` в `[0, 1]`; средний срок допускает осмысленные пропуски |
| Воспроизводимость | два запуска и запуск на переставленных строках совпадают после сортировки |
| Аудит | лог содержит validation → merge → feature build только для завершённых шагов |
| Scope | нет `churn`, fit модели и заявлений о причинности |
