# Артефакт модуля: preprocessing клиентов маркетплейса

**Тип:** функция preprocessing + preview-таблица признаков + короткий отчёт  
**Срок:** пара КТП **35**  
**Файл сдачи:** `features_preview.csv` + `REPORT` в ноутбуке `06_practice_pipeline`

---

## Задача

1. Собрать функцию `preprocess_customers(orders_df, customers_df, payments_df)`.
2. Провалидировать вход: отрицательные оплаты и пропуски ключевой даты должны вызывать `raise`.
3. Построить клиентскую таблицу с `Recency`, `Frequency`, `Monetary`.
4. Добавить минимум 1-2 инженерных признака (в модуле: `share_card`, `avg_days_to_deliver`).
5. Вернуть лог шагов обработки.
6. Сохранить preview результата в `features_preview.csv`.

---

## Критерии приёмки

| # | Критерий |
|---|---|
| 1 | В выходной таблице есть `customer_id`, `Recency`, `Frequency`, `Monetary` |
| 2 | Есть минимум один дополнительный признак сверх RFM |
| 3 | Валидация через `raise` действительно срабатывает на плохих строках |
| 4 | Лог шагов содержит не меньше 4 осмысленных шагов |
| 5 | `features_preview.csv` сохранён из рабочей функции |
| 6 | В отчёте описаны ограничения (slim-данные, без обучения модели) |
