# Lesson Design: Практика сборки preprocessing pipeline

## A. Сценарий пары

| Поле | Значение |
|---|---|
| Модуль | Feature Engineering и lambda (`08_05`) |
| Название урока | Практика сборки preprocessing pipeline |
| Пара КТП | **35** |
| Длительность | 2 академических часа (80 минут) |
| Роль | интеграция |
| Открыть | `lesson.ipynb` и slim CSV рядом |
| Минимум сдачи | `preprocess_customers`, features-таблица, лог, acceptance, `features_preview.csv`, `REPORT`, `READY` |
| Домашнее задание | `homework.ipynb` |
| Canvas | не опубликовано |

---

## B. Ход пары

| # | Этап | ~мин | Критерий закрытия |
|---|---|---|---|
| 1 | Каркас функции preprocessing | 15 | функция возвращает `(features, log)` |
| 2 | Сборка RFM + доппризнаков | 25 | обязательные столбцы присутствуют |
| 3 | Встроенная валидация входа | 15 | bad-case приводит к `raise` |
| 4 | acceptance + сохранение preview | 15 | `features_preview.csv` создан |
| 5 | Итоговый REPORT | 10 | `READY=True` при полном чек-листе |

---

## C. Если сбились

| Симптом | Действие учителя |
|---|---|
| Функция возвращает `None` | Разбить реализацию на этапы: validate -> merge -> aggregate |
| Колонки не совпадают с контрактом | Сверить `required_cols` до финального возврата |
| REPORT без фактов | Включить конкретные поля выхода и ограничения модуля |

---

## D. Проектирование

- Зачем урок: собрать итоговый артефакт модуля в форме повторно используемой функции.
- Центральная идея: preprocessing — инженерный продукт с контрактом и логом, а не разовый ноутбук.
- Домашнее задание: обязательно, с повторным запуском и рефлексией про следующий модуль.
