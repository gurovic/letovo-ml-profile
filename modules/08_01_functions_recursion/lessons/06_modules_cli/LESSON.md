### A. Чего хотим от пары

Главное — ученик видит разницу между **ноутбуком** (черновик: ячейки, состояние в памяти) и **модулем** (файл `.py`: функции с контрактом, которые импортируют и запускают заново каждый раз). К концу пары у него есть маленькая «библиотека» `metrics.py`, программа `main.py`, скрипт с аргументами и файл тестов — та же структура, что у стартового кода артефакта на паре 8.

Побочно закрываем три частых источника путаницы: почему `import` иногда печатает лишнее (`if __name__ == "__main__"`), почему после правки файла `import` «не видит» изменений (кэш модуля; новый процесс `python file.py` видит всегда), и что такое traceback с именем файла и номером строки.

Не вводим: `venv`, `pip`, пакеты с `__init__.py` как тему, `argparse`. Данные — те же `PREDICTIONS` / `LABELS`, что на паре 5.

## C. Если сбились

| Симптом | Что сказать |
|---|---|
| `python: command not found` / `'python' не является командой` | В Colab — ставить `!` в начале ячейки; локально попробовать `python3` или `py` |
| `ModuleNotFoundError: No module named 'metrics'` | Файл не создан или лежит в другой папке: `!ls` (локально `dir` / `ls`) — где `metrics.py`? |
| Правил `metrics.py`, а `import` возвращает старую версию | Модуль загружается один раз на процесс. Либо `python main.py` заново (новый процесс), либо `importlib.reload(metrics)`, либо «Среда выполнения → Перезапустить» |
| `import metrics` печатает отчёт | Код верхнего уровня выполняется при импорте. Спрятать под `if __name__ == "__main__":` |
| `predict.py` считает `"72" >= 60` → `TypeError` | `sys.argv` — строки; `int(sys.argv[1])` |
| `IndexError: list index out of range` в `predict.py` | Запустил без аргументов; `len(sys.argv)` проверить или дать значение по умолчанию |
| `AssertionError` без текста | Прочитать traceback снизу вверх: файл → строка → выражение. Добавить сообщение: `assert x == 3, "ожидали 3"` |
| «Зачем файл, если в ноутбуке работает?» | Файл можно импортировать в другую программу, запустить без Colab, проверить тестами. Артефакт пары 8 сдаётся именно файлами |

## D. Проектирование

### Зачем урок

Артефакт пары 8 сдаётся файлами: `text_stats.py`, `manual_tests.py`, `data/`. Без этой пары ученик впервые видит `import` своего модуля, `python manual_tests.py` и traceback прямо на итоговой работе. Ноутбуки следующих модулей тоже импортируют собственные `.py` (данные, утилиты).

### Центральная идея

| Поле | Значение |
|---|---|
| Центральная идея | Функции живут в файле-модуле: его импортируют, запускают из командной строки заново каждый раз и проверяют отдельным файлом тестов; ноутбук — черновик, модуль — продукт |
| Что поддерживает, но не отвлекает | `sys.argv`, `if __name__ == "__main__"`, traceback |
| Данные | `PREDICTIONS`, `LABELS` (пары 5); в блоке 6 — [data/module_datasets.py](../../data/module_datasets.py) через raw GitHub ([data/README.md](../../data/README.md)) |

### Результаты обучения

1. Объяснить разницу `.py` / `.ipynb` (текст кода vs JSON с ячейками и состоянием).
2. Создать модуль из своих функций и импортировать его двумя способами (`import m`, `from m import f`).
3. Запустить программу из командной строки с аргументами; объяснить `sys.argv` и `if __name__ == "__main__"`.
4. Написать файл тестов с `assert` и прочитать traceback (файл, строка, выражение).

### Data/ML-контекст

В проектах ML код живёт в модулях (`preprocess.py`, `metrics.py`, `train.py`), ноутбук — для исследования. `python train.py --threshold 0.6` — тот же `sys.argv`. Тесты метрик на маленьком примере — стандарт перед запуском на больших данных.

### Решения учащегося

1. Какие функции класть в один модуль (`metrics.py` vs всё в `main.py`).
2. Что оставить под `if __name__ == "__main__":`, а что — в тесты.
3. Как программа реагирует на отсутствие аргумента (ошибка или значение по умолчанию).
